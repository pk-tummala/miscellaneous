======================================================================
TRAP & CLEANUP - what happens to the lock file when a job dies at 3am
======================================================================

--- PART 1: the naive job (no cleanup) gets killed mid-run ---
  job_naive: acquired lock, working...
  [job killed]  lock file still there? -> YES
  the next run:
  job_naive: lock exists -> refusing to start (already running)
  => stuck. nothing runs again until a human deletes the lock by hand.

--- PART 2: the safe job (trap cleanup EXIT) gets killed mid-run ---
  job_safe: acquired lock, working...
  job_safe: cleanup ran (lock + temp removed)
  [job killed]  lock file still there? -> no
  the next run:
  job_safe: acquired lock, working...
  job_safe: finished
  job_safe: cleanup ran (lock + temp removed)
  => started clean. no stale lock, no pager, no human needed.

======================================================================
trap cleanup EXIT runs on normal exit, on errors, and on a kill (SIGTERM).
Add 'trap ... INT TERM' for a prompt Ctrl-C / kill. The only thing nothing
can catch is kill -9 (SIGKILL) - the OS stops you before any trap can run.
======================================================================
